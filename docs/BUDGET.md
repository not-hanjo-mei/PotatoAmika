# PotatoAmika 常驻内存账（实测版，2026-11-09）

口径：手机可用内存约 1.28 GiB（1,311 MB）。下面每个数都标了来源，开发机数和手机口径数分开列，混用时取对手机不利的一侧。

## 常驻账

| 组件 | 数字 | 来源 |
|---|---|---|
| 大脑 Minico（llama-server，12k 上下文） | 约 405 MB | 手机测速实测 4k 为 308 MB，每 1k 上下文约多 12 MB（开发机 llama-server 实测斜率）推到 12k；开发机 4k 实测 423 至 439 MB |
| 嵌入 Jina v5 nano（llama-server） | 约 150 MB | 开发机实测（调度器线）；文件 157 MB |
| TTS 宿主（自研引擎） | 262 至 280 MB | x86 宿主实测（ORT-FREE.md 第五节）；ORT 版为 292 至 315 MB |
| 耳朵 ASR 宿主（ORT，Moonshine 量化版加 VAD） | 154 至 178 MB | x86 实测（ASR.md）；手机是 musl ORT 1.24.4，数字可能不同 |
| 调度器（Go 静态二进制） | 约 8 MB | 开发机实测空载 RSS |
| 原版页适配器（Node 零依赖） | 约 38 至 54 MB | 预览机实测：空载 38 MB，转发合成音频后瞬时 54 MB（2026-11-09 魔改版） |
| 合计 | 约 1,019 至 1,075 MB | 按上行逐项相加（上下文已按用户 2026-11-09 决定从 4k 拉到 12k，多约 97 MB；适配器一行是 2026-11-09 用户定「手机上也要原版页」后新增） |
| 剩余 | 约 236 至 292 MB | 1,311 减合计 |

适配器不带第二份 TTS：原版页的向导台词与名字试听走调度器新增的 POST /v1/say，共用常驻的那份 tts_host（有回合在跑时回 409，契约在 scheduler/API.md）。预览机上适配器曾自拉一份 say 专用 tts_host（约 375 MB），手机账出不起，魔改时已砍掉，预览与手机从此同构，手机侧 TTS 永远只有一份。

原估算账是约 0.83 GiB（850 MB），实测比估算高约 35 至 75 MB，主要差在耳朵（估 80 MB、实测 154 至 178 MB）。合计仍在可用范围内，常驻本身不超。

## 眼睛的账

眼睛 LFM2.5-VL-450M 看图时峰值约 685 MB（x86 实测，VISION-REF.md），剩余空间装不下，拍照时必须先卸常驻件：

1. 只卸大脑：腾出约 405 MB，余量变约 641 至 697 MB，对 685 MB 峰值可能不够（适配器进账后更紧），不可行。
2. 卸大脑加嵌入：腾出约 555 MB，余量变约 791 至 847 MB，对峰值多出约 106 至 162 MB，可行（适配器在拍照时保持常驻，已计在内）。
3. 代价是拍完要重载大脑和嵌入：加载耗时手机未测（x86 热缓存口径大脑模型加载是秒级，手机冷加载会慢），拍照回合的体验是等十几秒量级，估算，未实测。

定法：拍照走第 2 条，卸大脑加嵌入，看完图再依次拉回。调度器实现时按这个顺序写，眼睛的峰值里包含它自己的 llama-server 进程开销，不要再另算一份。

已实现（2026-11-09，调度器 POST /v1/look，细节在 SCHEDULER.md 眼睛一节）：换载全程互斥，进程存活区间无重叠，有回合在途时拍照回 409、失败先恢复大脑与嵌入再报错。开发机实测（抢核环境、热缓存，耗时按上限口径）：整轮 20 至 34 秒，其中停 0.1 至 8.6 秒、视觉加载约 4 至 4.5 秒、答复 9.6 至 16 秒、卸载约 0.2 秒、重载约 5 至 5.5 秒；视觉峰值 VmHWM 682 MB，与 VISION-REF 的 685 MB 对得上。手机上冷加载会比这慢，整轮耗时与各步真数仍待上机。

## 还没数的

1. 手机真机上每个组件的实际 RSS，要等真机标定（合并标定包先测 TTS 两版；整机集成后还要再测一轮全家桶）。
2. 耳朵在 musl ORT 1.24.4 上的 RSS，可能与 x86 的 1.22.1 不同。
3. 大脑与嵌入在手机 aarch64 llama.cpp 构建上的 RSS（开发机是现构建的 x86 版，手机用 Alpine b9564 包或自建，数字会变）。
