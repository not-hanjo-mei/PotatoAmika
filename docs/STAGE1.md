## 转换与逐图校验

转换用 Genie-TTS 的 v2ProPlus 转换器（权重移植进模板图），产物为 graphs/fp32/（Genie 布局，合计 335,992,804 字节）。校验时把 bin 权重拼回自包含 fp32 图（work/fp32_full/），固定输入取 neutral1 参考、句子 S0，与上游 PyTorch 参考实现（GPT_SoVITS 仓固定提交 b4570b876f5c086819ba84e3215472733c6a7b70 的 AR.models.t2s_model_onnx 与 module.models）逐图对比。固定输入由 Genie 自身前端生成（ReferenceAudio 加 get_phones_and_bert），句子为下面 token 度量用的 3 句英文，参考音用 neutral1 与 caring1 两条。

| 图 | 对比量 | 最大绝对误差 |
|---|---|---|
| t2s_encoder | x 输出 | 1.48e-05 |
| t2s_encoder | prompts（语义码） | 0（逐值相等） |
| t2s_first_stage_decoder | y_emb | 0.0 |
| t2s_first_stage_decoder | 24 层 K / V | 1.11e-05 / 7.97e-06 |
| t2s_stage_decoder | y_emb（教师强迫 12 步） | 0.0 |
| t2s_stage_decoder | K（12 步内最大） | 7.87e-06 |
| prompt_encoder | ge | 3.81e-05 |
| prompt_encoder | ge_advanced | 1.91e-05 |
| vits | 650 个权重张量逐个核对 | 0.0（650/650） |
| vits | 音频输出（噪声置零对照，见下注） | 3.76e-05 |

注记：

- GPT 权重装进上游 Text2SemanticDecoder：missing 0、unexpected 0。SoVITS 权重装进 module.models.SynthesizerTrn（v2ProPlus）：unexpected 0；missing 的 103 个全是 enc_q（训练用的后验编码器，解码路径不用）。
- vits 的解码带随机噪声（图内 RandomNormalLike，noise scale 0.5 由图内常量 Constant_7 给出）。把校验副本里这个常量置零后，图输出与 PyTorch 解码（noise_scale=0）逐点对比得 3.76e-05。不置零时两个独立噪声抽样的相关性只有 0.56，这是模型本身的随机性，不是转换误差。另外实测该图跨会话可逐位复现（重跑差异 0.0）。
- 误差量级与 fp16 存储往返一致（Genie 布局的权重以 fp16 存放在 bin 里），vits 权重逐值相等说明这批权重本身恰好可被 fp16 精确表示。

## 量化做法与回退记录

预处理（两步都是语义不变的图重写，先后验过等价）：

1. 常量 Transpose 折叠：解码器图里 145 个 MatMul 只有 24 个直接吃权重，其余权重先过 Transpose 节点，ORT 动态量化器会跳过。把 Transpose（常量）折进权重后，折叠图与原图输出差异 0.0（编码器实测）。
2. weight_norm 折叠（仅 vits）：vits 里 180,828,672 字节是 weight_norm 的 g/v 参数对，卷积权重在运行时现算，静态量化器看不到。把 131 个卷积的 g/v 子图用 ORT 求值折成实际权重后，折叠图与原图输出差异 0.0。没有这一步，vits 的 QDQ 只能从 250 MB 降到 204 MB；折叠后降到 90 MB 级。

GPT 图：ORT quantize_dynamic，op 为 MatMul/Gemm，权重 QInt8。两张解码器逐通道成功（各自 307,212,868 降到约 80 MB）。SoVITS 两图：ORT quantize_static（QDQ 格式），校准集为固定输入的真实管线数据（prompt 用 2 条参考音，vits 用 2 参考乘 3 句共 6 组 fp32 管线产物），op 为 Conv/MatMul/Gemm，逐通道，激活与权重均 QInt8。

回退记录（int8 明显变差才回退，逐项列）：

1. **vits 的 enc_p 模块（81 个卷积）整组回退 fp32**，不走 QDQ。依据：全 QDQ 版 vits 在噪声置零对照下与 fp32 的相关性 0.859、相对 RMS 误差 0.534；分组归因实测（逐组排除量化、其余条件相同）：排除 enc_p 后 0.9513 / 0.3144，排除 flow 后 0.8803 / 0.4917，排除 dec 后 0.8828 / 0.4853，且排除 dec 还最贵。enc_p 是文本与语义编码器，它输出的分布参数对激活量化最敏感。回退粒度是模块而不是单层：81 层逐层猎杀的成本与收益不成比例，这里如实标注与"逐层"口径的出入。回退后 vits 为 131,687,271 字节（全 QDQ 版为 90,372,976 字节）。
2. **t2s_encoder 整图用逐张量动态量化**（7,555,286 字节）：逐通道模式在量化器内部触发 AssertionError，逐张量是工具级回退。该图小，未做逐层拆分。
3. prompt_encoder 未回退，但它是当前最小档里相对误差最大的一环：int8 版的 ge 与 fp32 的相对 RMS 误差 0.291（neutral1）与 0.271（caring1），相关性 0.956 与 0.963；ge_advanced 为 0.190 / 0.172，相关性 0.982 / 0.985。ge 的数值范围大（最大值 59 至 77，RMS 约 6），激活离群点把 int8 的尺度撑大了。若试听发现音色漂移，第一嫌疑就是它，可按单层回退处理。

量化后整图对照（固定输入，fp32 侧的 ge 与 token 喂同一个 vits，只换被测图）：

| 被测图 | 音频最大绝对误差 | 音频相关性 | 相对 RMS 误差 |
|---|---|---|---|
| vits 最小档（enc_p 回退版，噪声置零对照） | 0.4386 | 0.9513 | 0.3144 |
| vits 全 QDQ 版（已被回退版取代，噪声置零对照） | 0.4949 | 0.8586 | 0.5335 |
| vits W8 权重包烘焙版（带噪声） | 0.5298 | 0.9495 | 0.3190 |

说明：带噪声的最大绝对误差主要由波形高频相位决定，同一句话的两次独立噪声抽样之间最大误差也有 0.75，所以质量判断看相关性与相对 RMS 误差。最小档回退版的带噪声整图数未单独跑（去噪对照已足以定性），试听样本是最终判据。

## Token 一致性度量

为什么不用图内采样直接比：stage 图的采样在图内完成（top-k 加 Gumbel 噪声，重复惩罚 1.35），实测同一套 fp32 图跑两次，采样 token 的一致率只有 0.000 至 0.023、长度也不同，采样序列对比没有意义。改用贪心路径，两项指标：

- 教师强迫 top-1 一致率：把 fp32 的贪心轨迹逐步喂给被测配置的 stage 图，每步比 argmax（取图内重复惩罚后的 logits）是否等于 fp32 在该位置的 token。共 6 组输入（2 条参考音乘 3 句）合计 361 步。
- 自由贪心分叉点：两边各自贪心滚动，序列从第几个生成 token 开始不同。

fp32 贪心序列长度（生成部分）：neutral1 三句为 69、69、49；caring1 三句为 73、59、48。

| 配置 | 教师强迫一致率（合计） | 各组分档 |
|---|---|---|
| 最小档 GPT（int8 动态） | 347/361 = 96.12% | 66/68、64/68、45/48、70/72、56/58、46/47 |
| GPT W8 权重包 | 351/361 = 97.23% | 67/68、65/68、48/48、69/72、56/58、46/47 |
| GPT W4 权重包 | 299/361 = 82.83% | 57/68、59/68、42/48、57/72、42/58、42/47 |

自由贪心分叉点：18 个（配置乘输入）组合里 17 个在第 0 个生成 token 就分叉，只有最小档在 neutral1 加 S2 一组分叉于第 6 个。原因是第一个生成 token 由 first_stage 图内部采样产生（不是贪心 argmax），各配置抽到的不一样，后续贪心轨迹自然整体错位。这一项如实记录，但判读以教师强迫一致率为准。

结论（数据说话）：W8 权重包的一致率（97.23%）略高于 int8 动态档（96.12%），且 GPT 部分包体积（158,224,318）小于 int8 动态图（167,551,679）。W4 一致率 82.83%，体积 92,735,008，是三者最小。int8 动态档的优势是 ORT 可直接执行，权重包需要宿主做反量化或融合 kernel，这是阶段二选型要权衡的。

## 卡点与未尽事项

1. pth 文件头两字节被改（见输入清单），任何直接 torch.load 的下游都会踩，部署侧加载器需要带 Genie 式的修复逻辑，或在打包时换一个干净容器格式。
2. vits 的 enc_p 回退是模块级（81 层）而非逐层，与任务口径有出入，原因见回退记录 1。若阶段二要继续压体积，逐层猎杀 enc_p 内的敏感层是第一个候选，潜在回收上限约 41 MB（该模块 fp32 与 int8 的体积差）。
3. prompt_encoder 的 int8 相对误差偏大（见回退记录 3），未回退，等试听裁决。
4. 两张 GPT 解码器图在 Genie 布局与最小档里都共享权重；W8/W4 权重包是按图分别打的（gpt_first 与 gpt_stage 两包里有大量重复张量，逐字节同源），若阶段二采用权重包路线，包级去重还能再省约一半的解码器部分。本阶段未做包级去重，避免格式复杂化。
5. 本阶段全部工作在本机 CPU 上完成，未涉及手机与 Termux，未写 C++，未做任何训练。测速与真机标定不在本阶段范围内。
